# FILE_FORMATS.md — Форматы файлов КР1878ВЕ1

> Назначение: единая спецификация всех форматов файлов, с которыми работает набор инструментов.
> Статус полей: `[OK]` — подтверждено, `[GAP]` — не задокументировано, требует допущения/эмпирики.

---

## 1. Исходники ассемблера — `*.mic`

- Текстовый ISO-8859/ASCII; комментарий — `;` до конца строки.
- Обязательное расширение `.mic` для всех модулей.
- Многофайловость: `tessa file1+file2+...`; порядок модулей = порядок в командной строке.
- Каждый модуль заканчивается `.end`; вся программа — `.end`/`.endc`.

### Лексемы / число
| Форма | База |
|-------|------|
| `12` | десятичная |
| `12o` | восьмеричная |
| `0101b` | двоичная (суффикс `b`) |
| `12h` | шестнадцатеричная (суффикс `h`; ведущая цифра обязательна — `0FFh`) |

- Константа ≤ 8 бит; в адресах перехода расширяется до 12 бит.
- Числа 8-битные знаковые в двухостек (−128…+127).

### Идентификаторы
- **Метка (глобал)**: ≤32 символов, начинается с буквы, заканчивается `:`. Может «стакаться» (`l1:` `l2:` на одной строке).
- **Локальная метка**: `$` + только цифры (≤5), область = между соседними глобальными метками.
- **Константа**: имя ≤32 символа, первая буква; присваивается один раз глобально (`петя=40`).
- **Макрос**: `.macro имя p1,...,pN ... .endm`.
- **Метка макро**: `@` + цифры (автогенерация уникальных имён в раскрытии).

### Арифметические выражения
- Скобки `()`, операторы: `*`, `/`, `&` (AND), `+`, `-`, `\` (XOR), `!` (OR), `^` (инверсия/NOT).
- Унарные: `+`, `-`, `^`.
- Приоритет: 1) `()`; 2) `* / &`; 3) `+ - \ !`.
- `\` — XOR, `!` — OR (нестандартно!). `^` — NOT/инверсия.

### Псевдо-команды и директивы
| Директива | Описание |
|-----------|----------|
| `.byte c1,...` | байты данных в память команд |
| `.word c1/label,...` | 16-бит слова данных (метка как адрес) |
| `.even` | выровнять указатель на чётный адрес |
| `.` | текущий счётчик команд (можно `jmp .+1`) |
| `.=expr` | изменить счётчик при трансляции |
| `.if const ... .else ... .endif` | условная трансляция |
| `.bpt` | точка останова (макс. 4) |
| `.list mode` | битполе: bit0 include-файлы, bit1 раскрытие макcode, bit2 #define |
| `.end` | конец трансляции |
| `.endc` | конец + расчёт CRC (3 байта) в тело программы |
| `.macro name p1,..N` / `.endm` | объявление макро |
| `#include "file"` / `#include <lib>` | включение (lib — поиск в `-i:path`) |
| `#define идентификатор строка` | текстовый макро-заменитель |

### Доступ к регистрам (операнды)
- Память данных / I/O: `%a0..#d7` (префикс `%` опционален) — окно-сегмент.
- Сервисные регистры: `#0..#7` или `#a,#b,#c,#d`.
- Псевдо-загрузка адресов:
  - `mial dst,addr_ком` / `miah dst,addr_ком` — младшая/старшая часть адреса команды.
  - `mdal dst,addr_данных` / `mdah dst,addr_данных` — адрес данных (байт).
  - `ldal #6,label` / `ldah #7,label` / `lia #7,label` / `liah #7,label` — загрузка SR6/SR7 для IR1.
- Псевдо-инкременты: `inc X ≡ addl X,1`, `dec X ≡ subl X,1`, `clr X ≡ movl X,0`.

## 2. Исполняемый файл — `*.sav`

Порт VM+программатор → load. `[OK]` концепция, `[GAP]` точный бинарный вид.

Известные факты:
- Содержит образ **памяти команд** (16-бит слова); программator пробуфер 0x400 слов (1K×16).
- Загружается в «PC_ROM» (эмулятор/программатор); эмулятор: 16K×16 слов.
- `.endc` вычисляет контрольную сумму **3 байта** с переносами и кладёт её в тело программы (адресуется как данные).
- `*.SAV-File Read Error` — ошибка чтения в E03_PROG.

**Допущение (ADR-002):** сохранить `.sav` как последовательность 16-битных слов памяти команд в little-endian, без нетривиального заголовка (прямой образ), с опциональной служебной шапкой версии формата — НО совместимость с оригиналом требует, чтобы форма совпадала. Разделённый ресурс — полежать под вопросом до эмпирической проверки на реальном файле.

> ⚠️ **Важно:** поскольку точный формат `.sav` оригинала пока не восстановлен, реализация выводит `.sav` в согласованном каноническом виде и документирует его; на этапе этапа 4 (или при наличии реального образца) формата будет приведена к байт-совместимому оригинальному. Помечено в ADR.

## 3. Данные ЭСППЗУ данных — `*.dat` (текстовый)

Подтверждённый формат образца `EEPROM.DAT` (=64 байта):
- Байты разделяются пробелами, оформляются **двузначным hex** (`ff`).
- Строки по 8 байт; `;` — комментарий до конца строки.
- Файл оканчивается маркером `0x1A` (^Z, EOF).
- Парсер игнорирует не-hex токены, всё после `;`.
- Данных строго **64 байта** (ЭСППЗУ данных 64×8).

```
;Data EEPROM File (for Example).
ff ff ff ff ff ff ff ff ;0...7 Bytes
ff ff ff ff ff ff ff ff ;8...15 Bytes
ff ff ff ff ff ff ff ff ;16...23 Bytes
ff ff ff ff ff ff ff ff ;24...31 Bytes
ff ff ff ff ff ff ff ff ;32...39 Bytes
ff ff ff ff ff ff ff ff ;40...47 Bytes
ff ff ff ff ff ff ff ff ;48...55 Bytes
ff ff ff ff ff ff ff ff ;56...63 Bytes
```

## 4. Конфиг программatorа — `e03prg.arp` (32 байта)

| Смещение | Поле | Значение (LE DWORD) | Смысл |
|----------|------|---------------------|-------|
| 0x0 | MAIGC | `39 5A 3C 69` → 0x693C5A39 | константа-магия |
| 0x4 | prog_en | 0 | checkbox Program-write (0=вкл, 0xFFFFFFFF=выкл) |
| 0x8 | cfg_en | 0 | checkbox Config-write |
| 0xC | cfg2_en | 0xFFFFFFFF | доп. опция |
| 0x10 | data_ee | 0xFFFFFFFF | checkbox EEPROM/Data-write |
| 0x14 | erase_opt | 0xFFFFFFFF | опция erase/extended (0x01 = extended) |

В образце: Program-write=ON, Config-write=ON, EEPROM/Data-erase=OFF.

## 6. Вспомогательные файлы ассемблера

- `*.lst` — вкладываются листинг трансляции (генерируется при `-key l`).
- `*.sym` — символьная таблица для symbolic-debug (`-key d`).
- `*.sdf` — данные символической отладки (связанные с `.sym`).
- (Эмулятор также: `.trs` = trace, `.svg` = бинарный, `.bin` = эмуляц.)

## 7. Резюме обязательств для реализатора

- `assembler` crate: читает `.mic` → выдаёт `MemoryImage` (массив u16) + листинг + таблицу символов.
- `file-format` crate: читатель/письмователь `.sav`, `.dat`, `.arp`, `.lst`, `.sym`.
- Canonical: `.sav` сохраняется как little-endian u16 слова.
