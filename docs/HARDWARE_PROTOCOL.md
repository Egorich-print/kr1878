# HARDWARE_PROTOCOL.md — Аппаратный протокол программатора/отладки

> Восстановлено по дизассемблированию `E03_PROG.EXE`, `P_WMCT.EXE` и официального
> **`Uprg1878.exe`** (Lazarus/Free Pascal x86-64, без стриппинга символов + DWARF),
> даташит гл. 08–09.
> Цель: дать точный протокол для реализации `ProgrammerBackend` в Rust.

---

## 1. Интерфейсы оборудования (два НЕЗАВИСИМЫХ пути)

| Инструмент | Интерфейс | Адреса | Роль |
|------------|-----------|--------|------|
| **Программатор** (E03_PROG / P_WMCT) | **LPT1 (parallel)** | data `0x378`, status `0x379`, control `0x37A` | прошивка ЭСППЗУ команд + данных |
| **Отладочный модуль** (MC_WIN) | **COM (serial UART)** | COM1/COM2 (база на runtime) | встраиваемый отладчик/эмулятор |

### Распиновка LPT-битбанга (программатор)

Регистр **CONTROL (0x37A)** — тактируемые выходы кабеля:
| Бит control | Сигнала кабеля (из дизассемблера) | Функция |
|-------------|--------|----------|
| C0 (bit0) | STROBE/# | данные (передач) |
| C1 (bit1) | AutoFeed | тактовый (передач) |
| C2 (bit2) | INIT | тактовый (приём) |
| C3 (bit3) | SelectIn | командный/эраз импульс |

Регистр **STATUS (0x379)** — входы:
| Бит | Линия | Функция |
|-----|-------|---------|
| bit7 (инвертирован) | BUSY | данные (приём, `ReadBit7`) |
| bit6 | ACK | handshake готовности |

Регистр **DATA (0x378)** — командный байт-фазы: `0x38` / `0x3F` / `0x00`.

> Линия `BUSY` на выходе LPT конструктивно инвертируется (spike); декодер применяет инверсию (`in al,0x379; not al`).

> ⚠️ **TODO (валидация на железе):** реализация `lpt.rs` un-invert-ит и BUSY (bit7), и ACK (bit6)
> (см. ADR-004 §2). В документации оригинала инверсия упомянута только для BUSY.
> До проверки физического LPT договорённость о полярности гарантируется симуляцией
> (`InvertedStatusTransport` в `protocol::testutil`), но не подтверждена на реальном оборудовании.

## 2. Низкоуровневые примитивы (эквивалент Rust)

### 2.1 `OutCtrl(mask)` — запись комбинации control-битов в 0x37A
Параллельно кодированию по маске (C0..C3), с ресем инверсией C2 по умолчанию. (Детальный флаг-мативинг в RESERVER алге: overhead высчит-вовый.)

### 2.2 `ReadBit7()` / `ReadBit6()`
```rust
fn read_busy() -> bool { !(in_status(STATUS) >> 7) & 1 }  // 0x379 hbit7 инв.
fn read_ack()  -> bool { !(in_status(STATUS) >> 6) & 1 }
```

### 2.3 `WaitForAck(expected: bool)`
- Пульс ACK (status bit6) до равенства `expected`; либо до **10000 итераций** → «Microcontroller Not Ready».

### 2.4 `WriteBits(n, value)` — передача `n` бит MSB-first
```
1. idle: control ← 0x0F
2. Ждём ACK=1 (ждутся)
3. control &= ~1 ; control |= 1-й бит данных   // данные → C0
4. control ^= ~2 ; |2 ; control |= 2          // такт C1 (низ→выс)
5. битовой сдвиг value <<= 1; повторяя для всех n бит старшим вперёд
6. control ← 0x0F (idle)
```

### 2.5 `ReadBits(n)` — приём n бит
```
1. control ← 0x0F
2. wait ack high
3. data |= read_busy() << позиция;  value>>=1
4. control &= ~0x08 (trigger C3)       // find also - see
5. wait ack low
6. control ← 0x0F
   n == 8 → value >>= 8 (сдвиг байт)
```

### 2.6 Командный/эразовый импульс
```
control ← 0x0F
DATA(0x378) ← 0x38
loop 20× { control&~0x08; control|0x08 }   // toggle C3
DATA(0x378) ← 0x3F
```

### 2.7 Idle / off
```
control ← 0; DATA(0x378) ← 0x00
```

## 3. Протокол прошивания МК (алгоритм)

Выполняется для Program + Config + Data (ЭСПЗУ команд и данных):

```
1.  idle (control=0, DATA=0)
2.  ERASE  : командный импульс 0x38/0x3F, 20 toggle; WaitForAck
3.  WriteCommand: CMDWrite (командный код)            # команда = 0x03 для программatorа, 0x02 для данных
4.  WRITE program memory:
       for word in program_words (или for byte in data_bytes):
           WaitForAck                              # MC не готов пока занят
           WriteBits(16, word)                     # или WriteBits(8, byte)
5.  VERIFY (read-back):
       for each:
           value = ReadBits(16) (или ReadBits(8))
           if value != expected: "Programm Read Error" (или "Data Read Error") + трасса Address/Pattern/Data
```

Последовательность по состояниям диспетчера (E03_PROG):
1. Erase
2. ждать окончания / timeout → «Microcontroller Not Ready»/«Error»
3. CMDWrite (program) = код `0x03`
4. запись памяти программ (слова)
5. **Verify памяти программ** (ReadBits16)
6. CMDWrite (data) = код `0x02`
7. запись ЭСПРЗУ данных (байты)
8. **Verify данных** (ReadBits8)

`OSC_Configuration` — отдельный канал (ReadConfig), использует поле `0x4062BC`.

> `ERASE` из инспектируемого варианта используется отдельно (состояния 0–1), расширение — статус вариант в команде перед записью.

## 4. Абстракция для Rust

```rust
pub trait ProgrammerBackend {
    fn identify(&mut self) -> Result<DeviceId, Error>;
    fn erase(&mut self) -> Result<(), Error>;
    fn write_program(&mut self, words: &[u16]) -> Result<(), Error>;   // 16 бит
    fn write_data(&mut self, bytes: &[u8; 64]) -> Result<(), Error>;   // 8 бит
    fn read_program(&mut self) -> Result<Vec<u16>, Error>;
    fn read_data(&mut self) -> Result<[u8; 64], Error>;
    fn verify_program(&mut self, words: &[u16]) -> Result<bool, Error>;
    fn verify_data(&mut self, bytes: &[u8; 64]) -> Result<bool, Error>;
}
```

Реализации:
- `LptBackend` — прямое обращение к портам (Windows: `inpout32`/`inpoutx64`; Linux: `ppdev`/sysfs; macOS: недоступен без драйвера) — сохраняет совместимость с оригиналом.
- `UsbBridgeBackend` — современный USB-мост, работающий по тем же командам (простейший бейсик-исполнитель команд; логика — в Rust Core).
- `MockBackend` / `SimulatorBackend` — для юнит/интеграционных тестов и CI без железа.

## 5. Порядок инициализации питания МК

(из даташита, гл. 08, таблица 10)
- Программатор/модуль должен установить RST=0 (низ.), подать питание UCC ≥ 3.5V, затем RST→1 и выждать задержку начального запуска (счётчик 2^10 импульсов тактовой частоты). Это требуется для управляемого сброса и запуска — используется в reset delay (бит0 в `/c:NNN` P_WMCT).

## 6. COM-протокол отладочного модуля `[GAP]`

- Соединение COM1/COM2 почтовым UART, raw I/O.
- Команды: инициализация («Test Envelope» диагностика возврат ID/test-байт), `PC=0` сброс PC, загрузка `*.SAV` в память команд, чтение/запись ОЗУ/регистров, точки осненваново (SetBRK, до 4).
- **Точный байт-протокол не восстановлен статически** [GAP] — требует полного дизассемблирования MC_WIN или логического анализатора на реальном модуле. Этап отладки (часть 12) переносится в приоритет после заявленного core (прошивание) — фикс. см. ADR.

## 7. Официальный USB-программатор `Uprg1878.exe` (расшифрован)

В отличие от LPT-пути (§1–5), современный официальный инструмент Angstrom работает
**по COM-UART через USB-мост** и использует совершенно другую схему: блочную передачу
16 байт с байтовым подтверждением `'R'` (0x52) на каждый блок.

> Источник: полное дизассемблирование `BUTTON2CLICK` (0x100030560), локальных
> переменных из DWARF (`word_conf`, `txbuf[16]`, `rxbuf[16]`), форм-ресурса `.lfm`
> (Caption-ы контролов, Items RadioGroup) + структуры `TCOMPORTPARAMS`.
> Форма: `TForm1` из `unit1.pas`; `com_port.pas` — обёртка WinAPI
> `CreateFile/ReadFile/WriteFile/DCB/COMMTIMEOUTS/PurgeComm` с OVERLAPPED I/O.

### 7.1 Параметры порта

```
BaudRate = 38400   (0x9600)
ByteSize = 8
Parity   = NOPARITY (0)
StopBits = 1
Read/Write timeouts = 1000 мс (COMMTIMEOUTS, дважды 0x3E8)
```

### 7.2 Базовый обмен (после каждой посылки)

```
1. WRITE(buffer, 16)          # блок ровно 16 байт
2. PURGE (Rx, Tx)             # PurgeComm(0x0F): TX/RX abort + clear
3. DRAIN:                     # приём до тишины 80 мс
     loop:
       n = READ(&b, 1, timeout=80 мс)     # ReadFile + WaitForSingleObject(80)
       if n != 0: last = b; continue      # байт пришёл — сливаем дальше
       break                              # тишина: приём завершён
   require last == 'R' (0x52)
```

Ответ **'R'** = подтверждение приёма блока прошивальщиком. Хост ждёт **тишину**
(паузу ≥80 мс без байт) и требует, чтобы последний принятый байт был `'R'`.
Это правило применяется после **каждого** блока (фаз A–E), поэтому каждый блок
стоит ≥80 мс. Внутри фаз байтовая пауза между соседними блоками ≤80 мс — иначе
последовательность собьётся (на реальном устройстве не проверялось).

### 7.3 Последовательность прошивания (порядок строго фиксирован)

```
0. OPEN(COM, params); PURGE
1. Собрать 16-бит слово конфигурации cfg (см. §7.5):
   word_conf := 0
   if CheckBox "Задержка" (RDE): word_conf |= 0x0007
   RadioGroup "Генератор" ItemIndex:
     0 (RC)            -> 0x0000
     1 (Внутренний)    -> 0x01C0
     2 (Кварц >500кГц) -> 0x0038   # ItemIndex по умолчанию = 2
     3 (Кварц <500кГц) -> 0x01F8
2. ФАЗА 0 — СТИРАНИЕ/СИНХРОНИЗАЦИЯ:
   WRITE(txbuf,16) где txbuf НЕ инициализирован (мусор стека);
   PURGE; DRAIN-'R'
   # содержимое первого блока для хоста неважно; статус "Стирание".
   # Rust-реплика может слать любой блок (рекоменд. 0xFF×16) — [GAP] на железе.
3. ФАЗА A — DATA EEPROM, 1-й проход (если ISDATA=1):
   SEEK(F_EEM, 0)
   for i in 1..4:                        # 4 блока × 16 байт = 64 байта
     for j in 0..15:
       if not EOF(F_EEM): txbuf[j] = байт из F_EEM
       else:              txbuf[j] = 0xFF
     WRITE(txbuf,16); PURGE; DRAIN-'R'
4. ФАЗА B — DATA EEPROM, 2-й проход ("верификация данных"):
   SEEK(F_EEM, 0) снова; 4×16 как фаза A
   # данные пишутся ДВАЖДЫ; это повторная запись, не read-back
5. ФАЗА C — PROGRAM MEMORY, 1-й проход (.sav):
   SEEK(F_W, 0x100)                    # 256 СЛОВ = 512 байт заголовка .sav!
   for i in 1..128:                    # 128 блоков × 16 байт = 1024 слова
     for j in 0..7:                    # 8 слов по 2 байта
       if not EOF(F_W):
         w = u16 из F_W (file of Word)
         txbuf[2j+0] = hi(w)           # big-endian в блоке
         txbuf[2j+1] = lo(w)
       else: txbuf[2j..2j+1] = 0xFF, 0xFF
     WRITE(txbuf,16); PURGE; DRAIN-'R'
6. ФАЗА D — КОНФИГУРАЦИОННОЕ СЛОВО:
   txbuf[0] = hi(word_conf); txbuf[1] = lo(word_conf)   # остальные байты стейл
   WRITE(txbuf,16); PURGE; DRAIN-'R' (таймаут 1000 мс — конфиг пишется дольше)
7. ФАЗА E — PROGRAM MEMORY, 2-й проход ("верификация кода"):
   SEEK(F_W, 0x100); 128 блоков × 16 как фаза C
8. status := "Выполнено"; CLOSE
```

**Важно:** «Верификация» в фазах B/E — это **повторная запись**, а не чтение.
Инструмент никогда не читает содержимое микросхемы и не сравнивает его (read-back
в протоколе отсутствует; только подтверждения `'R'` на запись).

### 7.4 Ключевые отличия от LPT-протокола

| Аспект | LPT (§1–5) | USB/COM (эта глава) |
|--------|------------|---------------------|
| Интерфейс | Параллельный порт 0x378/379/37A | UART 38400-8N1 через USB-мост |
| Единица обмена | биты (WriteBits/ReadBits) | блоки ровно 16 байт |
| Подтверждение | ACK/готовность (bit6/bit7 status) | байт `'R'` (0x52), ожидание тишины |
| Командные коды | `0x38`/`0x3F` на шине DATA | нет; конфигурация в слове cfg |
| Верификация | явный read-back (ReadBits16/8) | повторная запись (фазы B/E) |
| Data EEPROM | 64 байта, единоразово | 64 байта × 2 прохода |
| Program | слова с начала .sav | с пропуском 256 слов (0x100) заголовка |
| Порядок байт в слове | (см. §2) | big-endian: hi байт первым |
| Конфигурация | канал OSC (CMD_CONFIG=0x01) | 16-бит слово, биты утроены (см. §7.5) |

### 7.5 Конфигурационное слово (RDE / OT1 / OT2, биты утроены)

Из даташита (кодирование ЭСППЗУ): каждый логический разряд строки конфигурации
повторяется в ЭСППЗУ **трижды подряд**. Строка конфигурации — 1025-е слово
памяти команд (адрес 0x400). Разряды:

| Разряд | Назначение (логический бит) | Физический сдвиг (×3) |
|--------|------------------------------|------------------------|
| RDE | Разрешение счётчика задержки начального запуска | биты 0–2 (маска 0x07) |
| OT1 | Режим генератора, старший бит | биты 3–5 (маска 0x38) |
| OT2 | Режим генератора, младший бит | биты 6–8 (маска 0x1C0) |

Режимы генератора (OT1,OT2):

| OT1 | OT2 | Режим |
|-----|-----|-------|
| 0 | 0 | внешний RC |
| 1 | 0 | внешний кварц 500 кГц – 8 МГц |
| 1 | 1 | внешний кварц до 500 кГц (с внешним перекл. генератора) |
| 0 | 1 | внутренний генератор ~50 кГц |

Графический выбор отображается в 16-бит слово `word_conf` (RadioGroup «Генератор»
в `Uprg1878.exe`): «RC»→0x0000, «Внутренний»→0x01C0, «Кварц >500кГц»→0x0038,
«Кварц <500кГц»→0x01F8; чекбокс «Задержка» добавляет RDE → 0x0007. Старшие биты
9–15 не используются (всегда 0).

> ⚠️ **Расхождение с нашими текущими реализациями** (см. ADR-005): наш `Mock/Sim/LPT`
> предполагает CMDWrite коды `0x03` (program) / `0x02` (data), явный read-back verify
> и передачу слов с начала `.sav` (без заголовка). Официальный `Uprg1878.exe`
> использует 16-байтовые блоки, `'R'`-подтверждения и **пропускает 256 слов
> заголовка `.sav`** (наш формат `.sav` — без заголовка; файлы Angstrom/TESSA —
> с 256-словным заголовком, см. `crates/file-format`). Совместимость с Uprg1878
> реализована как `UsbBridgeBackend` в `crates/programmer` (см. ADR-005).
