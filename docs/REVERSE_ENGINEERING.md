# REVERSE_ENGINEERING.md — Восстановленная спецификация КР1878ВЕ1

> Источник истины: даташит (док. 00), «Система команд» (гл. 05), «ТЕСЕЙ» (гл. 10–12),
> анализ бинарников `E03_PROG.EXE`, `P_WMCT.EXE`, `MC_WIN.EXE`.
> Точность: бит-уровневые опкоды извлечены из таблиц даташита; протокол программatorа — из дизассемблирования.
> Открытые вопросы явно помечены `[GAP]`.

---

## 1. Архитектура микроконтроллера (Harvard RISC)

| Параметр | Значение |
|----------|----------|
| Ядро | «Тесей», CMOS, Harvard, RISC |
| Разрядность команд | **16 бит**, фиксированная (1 слово = 1 команда) |
| Разрядность данных | 8 бит (байт) |
| Память команд | ЭСППЗУ **1К × 16** (1024 слова), адрес 10 бит; варианты эмулятора 16К×16 |
| Память данных | единое пространство **256 байт**: периферия 0x00–0x3F, ОЗУ 0x40–0xBF (128), ЭСППЗУ данных 0xC0–0xFF (64) |
| Регистровый файл | нет классических РОН; 32 виртуальных 8-бит регистра через 4 окна (сегмента) A/B/C/D по 8 байт |
| Исполнение | 4-стадийный конвейер; любая команда = **2 такта** |
| Кол-во команд | 52 |

**Стеки (аппаратные):**
- **Стек команд** `8 × 10` бит (8 уровней), указатель **ISP** (0–7): адреса возврата JSR/IJSR/прерываний.
- **Стек данных** `16 × 8` байт, указатель **DSP** (0–15): PUSH/POP SR и автосохранение RS на прерывании.
- `JSR/IJSR/прерывание`: `ISP+1`; `RTS/RTI`: `ISP−1`; `SKSP`: `ISP−1` без извлечения.
- Переполнение ISP=7 / DSP=15 или опустошение ISP=0 / DSP=0 → **stack-fault прерывание**.
- `RESET`: ISP=0, DSP=0.
- `WAIT` — ожидание прерывания (генератор работает); `STOP` — остановка с выключением генератора.

## 2. Адресация операндов

- Поле операнда = **5 бит**: `bit4-3` сегмент (00=A, 01=B, 10=C, 11=D), `bit2-0` индекс 0–7 внутри окна.
- **Эффективный адрес** = (база сегмента из SR0–SR3) + индекс.
- Индексы **6 и 7 сегмента D** — косвенная адресация:
  - `D6 → IR0` (регистр косвенной адресации 0), `D7 → IR1` (IR1).
  - IR0/IR1 режимы: выкл / автоинкремент / автодекремент (±1 после доступа), выбор режима через `LDR` (старшие 2 бита).
  - IR1 имеет режим адресации к **памяти команд** (байтовый адрес = SR6 + 3 младших бита SR7), автоинкремент.
- Периферийные регистры доступны как обычная память данных (указанием сегмента на 0x00–0x3F).
- Синтаксис ассемблера: `%a0..%d7` и без префикса `a0..d7` — эквивалентно.

## 3. Сервисные регистры (SR0–SR7)

| # | Название | Функция |
|---|----------|---------|
| 0 | SR0 | База сегмента A |
| 1 | SR1 | База сегмента B |
| 2 | SR2 | База сегмента C |
| 3 | SR3 | База сегмента D |
| 4 | SR4 | IR0 — адрес косвенной адресации (часть) |
| 5 | SR5 | IR0 — адрес (часть) |
| 6 | SR6 | IR1 — адрес (старший байт, режим памяти команд) |
| 7 | SR7 | IR1 — адрес (младшие 3 бита используются в режиме памяти команд) |

Доступ к SR — только `LDR`, `MFPR`, `MTPR`, `PUSH`, `POP`.
Мнемоника в ассемблере: `#0..#7` или буквы `#a,#b,#c,#d` для SR0–SR3.

## 4. Регистр состояния процессора (RS)

```
 7    6    5    4    3    2    1    0
RES  RES  DC   OF   IE   S    Z    C
```

- **C** (bit0) — перенос; **Z** (bit1) — ноль; **S** (bit2) — знак.
- **IE** (bit3) — разрешение прерываний (устанавливается WAIT/STOP/SST).
- **OF** (bit4) — арифметическое переполнение; **DC** (bit5) — десятичный (полубайтовый) перенос.
- OF и DC «одноразовые»: устанавливаются арифметикой, сбрасываются следующей командой; проверяются через `TOF`/`TDC` (→ Z).
- RS доступен по чтению по физическому адресу памяти **0x00**.
- На прерывании RS автоматически сохраняется в стек данных, `RTI` восстанавливает.

### Влияние команд на флаги

| Группа | Z | S | C | OF | DC |
|--------|---|---|---|---|---|
| MOV/MOVL | * | * | – | сброс | – |
| ADD/SUB/ADDL/SUBL/ADC/SBC | * | * | * | * | * |
| CMP/CMPL | * | * | * | * | * |
| AND/OR/XOR/NOT/SWAP/BIC/BIS/BTG/BTT | * | * | сброс | сброс | сброс |
| SHL/RLC | * | * | * (=бит) | сброс | сброс |
| SHR/SHRA | * | сброс | * | сброс | сброс |
| LDR/MFPR/MTPR/PUSH/POP | – | – | – | – | – |

## 5. Система команд — полная таблица с кодами

Обозначения: `s=src`, `d=dst`, `c=const`, `p=положение тетрады`, `a=адрес(10 бит)`, `n=№ сервисного регистра (3 бита)`, `m=маска битов RS (4 бита)`. Бит 15 — старший.

### 5.1 Двухоперандные: `биты 15..10 opcode(6) | 9..5 src(5) | 4..0 dst(5)`

| Мнемоника | opcode | Действие | RS |
|-----------|--------|----------|----|
| MOV d,s | `000001` | s→d | Z,S; OF=0 |
| CMP d,s | `000010` | d−s (без записи) | S,Z,C,OF,DC |
| SUB d,s | `000011` | d−s→d | S,Z,C,OF,DC |
| ADD d,s | `000100` | d+s→d | S,Z,C,OF,DC |
| AND d,s | `000101` | d&s→d | Z,S; C=0,OF=0,DC=0 |
| OR  d,s | `000110` | d\|s→d | Z,S; C=0,OF=0,DC=0 |
| XOR d,s | `000111` | d^s→d | Z,S; C=0,OF=0,DC=0 |

### 5.2 Литеральные команды

**MOVL / CMPL** — `биты 15..13 opcode(3) | 12..5 const(8) | 4..0 dst(5)`:
| Мнемоника | opcode | Действие |
|-----------|--------|----------|
| MOVL d,const | `010` | const→d (CLR ≡ MOVL d,0) |
| CMPL d,const | `011` | d−const → S,Z,C,OF,DC |

**ADDL / SUBL** — `биты 15..10 opcode(6) | 9..5 sconst(5) | 4..0 dst(5)`:
| Мнемоника | opcode | Действие |
|-----------|--------|----------|
| ADDL d,sconst | `001100` | d+sconst→d (INC ≡ ADDL d,1) |
| SUBL d,sconst | `001011` | d−sconst→d (DEC ≡ SUBL d,1) |

**BIC / BIS / BTG / BTT** — `биты 15..10 opcode(6) | 9 p(1) | 8..5 tconst(4) | 4..0 dst(5)`:
| Мнемоника | opcode | p=1 | p=0 | Действие |
|-----------|--------|-----|-----|----------|
| BIC d,tconst | `001010` | BICH | BICL | d & ~tconst → d |
| BIS d,tconst | `001110` | BISH | BISL | d \| tconst → d |
| BTG d,tconst | `001111` | BTGH | BTGL | d ^ tconst → d |
| BTT d,tconst | `001101` | BTTH | BTTL | d & tconst → Z,S |

### 5.3 Однооперандные: `биты 15..5 opcode(11) | 4..0 dst(5)`

| Мнемоника | opcode (11 бит) | Действие | RS |
|-----------|-----------------|----------|----|
| SWAP d | `00000000001` | обмен тетрад | Z,S; C=OF=DC=0 |
| NEG d | `00000000010` | −d→d | Z,S,OF,C,DC |
| NOT d | `00000000011` | ~d→d | Z,S; OF=0 |
| SHL d | `00000000100` | сдвиг влево, 0→d0, d7→C | Z,S; C=d7; DC=0 |
| SHR d | `00000000101` | сдвиг вправо лог., d0→C | Z; S=0; C=d0 |
| SHRA d | `00000000110` | сдвиг вправо арифм. | Z,S; C=d0 |
| RLC d | `00000000111` | вращение влево через C | Z,S; C=d7 |
| RRC d | `00000001000` | вращение вправо через C | Z,S; C=d0 |
| ADC d | `00000001001` | d+C→d | Z,S,OF,C,DC |
| SBC d | `00000001010` | d−C→d | Z,S,OF,C,DC |

### 5.4 Сервисные регистры и RS

| Мнемоника | Кодировка | Действие |
|-----------|-----------|----------|
| LDR n,const | `00100` + const(8) + n(3) | const→SR[n] |
| MFPR d,n | `00000011` + n(3) + d(5) | SR[n]→d |
| MTPR n,s | `00000010` + n(3) + s(5) | s→SR[n] |
| PUSH n | `0000000000010` + n(3) | SR[n]→стек данных; DSP+1 |
| POP n | `0000000000011` + n(3) | стек→SR[n]; DSP−1 |
| SST m | `000000011000` + m(4) | установить биты RS |
| CST m | `000000011100` + m(4) | сбросить биты RS |
| TOF | `0000000000000100` | OF→Z |
| TDC | `0000000000000101` | DC→Z |

### 5.5 Передача управления: `биты 15..12 opcode(4) | 11..0 адрес(12)`

> **Уточнение (2026-08-11):** ветвления используют **4-битный опкод** в битах
> 15..12 и **12-битный абсолютный адрес**, а не 6-битный опкод с 10-битным
> адресом, как предполагалось ранее. Это устраняет коллизию с 6-битными
> литеральными опкодами (`ADDL=001100`, `SUBL=001011`, `BIC=001010` и др.).
> Подтверждено даташитом (гл. 05: «Код команды: 1000 address» и т.д.) и
> проверено round-trip `encode/decode` в `crates/core/src/isa.rs`.

| Мнемоника | opcode (4 бита) | Условие |
|-----------|-----------------|---------|
| JMP a | `1000` | безусловный |
| JSR a | `1001` | вызов подпрограммы |
| JZ / JEQ a | `1010` | Z=1 |
| JNZ / JNE a | `1011` | Z=0 |
| JNS a | `1100` | S=0 |
| JS a | `1101` | S=1 |
| JNC a | `1110` | C=0 |
| JC a | `1111` | C=1 |

### 5.6 Фиксированные (16-бит слово)

| Мнемоника | Слово | Действие |
|-----------|-------|----------|
| NOP | `0000` | нет операции |
| WAIT | `0001` | ждать прерывания; IE=1 |
| RESET | `0002` | ISP=0, DSP=0; сброс stack-fault |
| IJMP | `0003` | IR1(младшие 10 бит)→PC |
| TOF | `0004` | OF→Z |
| TDC | `0005` | DC→Z |
| SKSP | `0006` | ISP−1 (выброс уровня возврата) |
| IJSR | `0007` | PC→истек; IR1→PC; ISP+1 |
| STOP | `0008` | остановка; генератор off; IE=1 |
| RTS | `000C` | истек→PC; ISP−1 |
| RTI | `000D` | истек→PC; стек→RS; ISP−1, DSP−1 |
| RTSC c | `000E`/`000F` (LSB=c) | истек→PC; c→C; ISP−1 |

`[GAP]` RTSC кодировка показана как `000E` (c=0) / `000F` (c=1) — бит0 слова = c (уточнить по эмпирике).

## 6. Векторы прерываний

| Вектор (адрес слова) | Источник |
|----------------------|----------|
| 0 | начальный запуск (reset) |
| 1 | системная ошибка (в т.ч. stack-fault) |
| 3 | сторожевой таймер |
| 6 | порт A |
| 7 | порт B |
| 0xF (15) | таймер + завершение записи ЭСППЗУ |

Первые 16 слов памяти команд (0x000–0x00F) всегда зарезервированы под вектора (в примере — `jmp START`, `nop`…).

## 7. Итоги обратного проектирования бинарников

### 7.1 `E03_PROG.EXE` (Win95, MFC, ~24 KB)
- Порты: **LPT1** — `0x378` (data), `0x379` (status), `0x37A` (control). Адреса зашиты (не конфигурируются).
- Примитивы битбанга (подтверждены дизассемблированием):
  - `WriteBits(n,val)` — передача n бит MSB-first: **данные = control bit0**, **тактовый = control bit1**, фрейм старт/стоп по ACK (status bit6).
  - `ReadBits(n)` — чтение n бит: **данные = BUSY (status bit7)**, **тактовый = control bit2**.
  - `WaitForAck` — опрос ACK до 10000 итераций (timeout).
- Командный импульс эраза: `DATA=0x38`, 20 переключений control bit3, `DATA=0x3F`.
- Конфиг `e03prg.arp`: магия `0x693C5A39` (bytes `39 5A 3C 69`) + 5 DWORD опций (0xFFFFFFFF = выкл, 0 = вкл) → выбор Program-write / Config-write / EEPROM-write / erase-mode.
- Последовательность прошивки: **Erase → CMDWrite(0x03) → запись программatorом 16-бит слов → Verify (ReadBits16) → CMDWrite(0x02) → запись ЭСППЗУ данных (8 бит) → Verify**.
- `*.SAV` — программatorом: 0x400 слов (1K × 16).

### 7.2 `P_WMCT.EXE` (DOS)
- LPT-программator: `0x378/0x379/0x37A`, битбанг, `int 15h AH=86h` для задержек (~3.2 s reset pulse).
- Буфер командной ЭСППЗУ = **1024 байта** (mov cx,1024), данных = **64 байта**.
- CLI: `P_WMCT.EXE *.SAV [/c:NNN] [/d:EEPROM]`; `/c` биты: bit0 reset delay, bits1-2 осцилятор (00 RC / 01 кварц>100кГц / 10 внутренний ~50кГц / 11 кварц<100кГц).

### 7.3 `MC_WIN.EXE` (DOS debugger)
- GUI «Icon Box 98.04», COM1/COM2 (база резолвится на runtime), raw `in/out` (без int 14h).
- Загружает `*.SAV` (PC_ROM), работает с `.sym`/`.sdf` (символы), `.trs` (trace).
- Внутренний дизассемблер подтверждает набор мнемоник ISA (см. §5).

## 9. Открытые вопросы `[GAP]` (резолюция)

1. **Точный бинарный формат `.sav`** (заголовок, адресная карта, порядок байт). Эмпирическая проверка на реальном образце, либо соглашение «прямой образ памяти команд» (см. FILE_FORMATS.md, ADR).
2. **Командные коды 0x01/0x02/0x03** (CMDWrite) — соответствие «запись программatorом/данными/OSC»; подтверждается даташитом гл. 09.
3. **Баудрейт COM** MC_WIN — не восстановлен статически (стандартное допущение 9600/19200).
4. Точная разводка пинов LPT↔МК (бит0/бит1/бит2 control ↔ сигналы чипа) — восстановлена логически, требует сверки с аппаратной документацией программатора.
5. `RTSC` кодировка — уточнить.
