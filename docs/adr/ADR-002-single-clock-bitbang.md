# ADR-002 — Протокол битбанга: одноклоковое тактирование

## Статус
Принят (2026-08-06).

## Контекст
В первичной реализации `protocol::bits`:
- запись и чтение разделяли один регистр управления (CONTROL), в котором линии C1 (write clock) и C2 (read clock) присутствовали одновременно;
- симулятор тактировал чтение по *уровню* (а не по фронту), из-за чего счётчик чтения «перетекал» на запись и смещал все биты чтения.

Итог: нулевой readback и лишний ведущий бит.

## Решение
1. `write_bits` тактирует **только** C1 (C2 не трогается); `read_bits` тактирует **только** C2 (C1 не трогается).
2. Запись одного бита: сброс C1 → выставление уровня на C0 → подъём C1 (фронт фиксирует бит); выход в idle не создаёт edge.
3. Чтение одного бита: фронт C2 → семпл BUSY.
4. Стартовое/финальное состояние — idle (`CONTROL_IDLE`), чтобы первая запись в функцию не считалась битом.
5. На уровне `device` чтение повторно выбирает память (`select(CMD_*)`); симулятор сбрасывает счётчик чтения при `select`.

## Следствия
- Round-trip слов и байт корректен (14 тестов protocol, все зелёные).
- Стирающий импульс не даёт «ложных» бит (запись тактируется только при `last_code ∈ {CMD_PROGRAM, CMD_DATA}`).

## Альтернативы
- Двойное тактирование (обе линии на каждую операцию): отвергнуто как конфликтное для раздельной памяти чтения/записи.
- Усложнённое отслеживание фреймов: отвергнуто, т.к. маскировало разбаланс длины бит, а не исправляло его.
