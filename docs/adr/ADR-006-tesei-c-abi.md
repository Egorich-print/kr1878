# ADR-006 — ABI компилятора C для ядра ТЕСЕЙ

## Статус
Принят (2026-11-03). Реализован в `crates/kr1878-cc` (бэкенд
`vendor/chibicc/tesei_codegen.c`).

## 1. Контекст

Ядро ТЕСЕЙ — гарвардский 8-битный RISC **без единого общего регистра**:
операнд — это байт 256-байтного ОЗУ, адрес которого равен
`SR[сегмент] + индекс` (`crates/core/src/cpu.rs:219-226`). Дополнительно:

* ОЗУ — 128 байт (0x40…0xBF), ПЗУ команд — 1024 слова по 16 бит;
* стек данных — 16 байт и **не адресуем**; стек команд — 8 уровней, в нём
  лежит только адрес возврата → **рекурсия невозможна**, глубина вызовов ≤ 8;
* нет деления, умножения и плавающей точки;
* 16-битный адрес грузится двумя байтами, переходы только абсолютные.

Обычные компиляторы (LLVM, GCC) построены на противоположных допущениях —
аллокация регистров, frame pointer, адресуемый стек, — поэтому их бэкенд
для ТЕСЕЙ пришлось бы изобретать с нуля (оценка 12–20 месяцев, см.
`docs/TOOLCHAIN_OPTIONS.md`). Решено писать собственный бэкенд к
фронтенду chibicc (MIT) — тогда язык C появляется за 9–18 недель.

## 2. Решение

### 2.1 Модель памяти

Три ячейки ОЗУ зарезервированы компилятором:

| Адрес | Имя | Назначение |
|---|---|---|
| 0x40 | `%b0` | scratch — единственный способ занести значение в служебный регистр (`mtpr n, %b0`) |
| 0x41 | `%b1` | аккумулятор (ACC) — значение каждого выражения |
| 0x42 | `%b2` | ячейка возврата (RET) |

Переменные (глобальные, локальные, параметры) начинаются с 0x43.

`SR1` (сегмент B) закреплён за 0x40, поэтому `%b0`/`%b1`/`%b2` имеют
постоянные адреса. `SR0` используется как временный регистр (T0), а стек
данных (DSP) — как стек значений для вложенных выражений и аргументов.
`IR0` (`SR5:SR4`) — регистр адреса данных; `SR5` не пишется, поэтому
`IR0 == SR4` (адрес 8-битный, чего хватает на всё ОЗУ).

### 2.2 Кадры

Кадры **статические**: у ядра нет адресуемого стека, а стек команд хранит
только адрес возврата. Каждая функция получает свой участок ОЗУ при
разметке; рекурсия запрещена (и невозможна физически), глубина вызовов
ограничена восемью уровнями аппаратного стека.

### 2.3 Соглашение о вызовах

* Аргументы кладутся на стек данных в **обратном порядке**, поэтому
  вызываемая функция снимает их (`pop`) в порядке объявления.
* Параметры сразу переносятся в свои статические ячейки (пролог функции).
* Возвращаемое значение — в ячейке RET (0x42); вызывающий забирает его
  сразу после `jsr`.
* Регистры не сохраняются: их нет. Порядок вычисления аргументов не
  определён (как и в C).

### 2.4 Кодирование выражений

* `a + b`, `a & b`, … — двухоперандные: `acc op acc` через scratch.
* Вычитание: `sub %b0, %b1` (в scratch — левый операнд, в аккумуляторе —
  правый), результат переносится обратно.
* Сравнения: вычисляется `lhs - rhs`, дальше `Z` (равенство) и `S`
  (знак, т. е. «меньше» для знаковых 8-битных значений). Условия в
  ветвлениях компилируются **в переходы**, а не в значение 0/1, — это
  заметно экономит слова ПЗУ.
* Сдвиги выполняются по одному биту (`shl`/`shr` — сдвиг на 1), поэтому
  `a << n` разворачивается в n инструкций.
* Умножение, деление и остаток **не реализованы**: им нужен рантайм,
  а без него диагностика честнее, чем неверный результат. Реализация
  через сдвиги и вычитание — следующий инкремент.

### 2.5 Точка входа

Стартап формирует бэкенд: 16 слов векторов прерываний (`jmp _start`,
остальные — `jmp` обработчика по умолчанию), установка `SR1 = 0x40`,
инициализация глобальных переменных, вызов `main` и вечный цикл.

## 3. Следствия

* Код C для ТЕСЕЙ — это C без `float`, без `long`, без рекурсии и с
  глубиной вызовов не больше восьми; ограничения проверяются компилятором
  (неизвестная конструкция даёт внятную ошибку, а не неверный код).
* Код программы заметно больше, чем на обычном процессоре: любое
  обращение к переменной стоит 2–4 команды, а любое сравнение — ещё и
  переходы. Это делает **размер** главным ограничением (см. §5).
* Расширять фронтенд не нужно: всё, что поддерживает chibicc, работает
  сразу, кроме constructs, перечисленных в §2.4.

## 4. Альтернативы

* **LLVM-бэкенд** — даёт C, C++, Zig и Rust разом, но 12–20 месяцев и
  изобретение calling convention с нуля; отложен на «год 2+».
* **Порт vbcc** — втрое меньше кода, но лицензия требует письменного
  согласия автора для коммерческого использования.
* **Свой фронтенд C на Rust** — 8–10 тысяч строк вместо готовых 7 300;
  отвергнуто.

## 5. Проверено

* 9 golden-тестов (`crates/kr1878-cc/tests/golden.rs`): арифметика,
  локальные и глобальные переменные, сравнения, `if/else`, `while`,
  вызовы функций с аргументами и вложенные вызовы — C → ассемблер →
  симулятор → результат.
* Попутно найден и исправлен дефект ассемблера: `tetrad_place()` снимал
  суффикс `l`/`h` с **любой** мнемоники, из-за чего `push` и `shl`
  перехватывались битовым армом (регрессия — `crates/assembler/tests/mnemonics.rs`).
